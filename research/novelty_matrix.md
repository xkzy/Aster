# Novelty matrix (interim, cutoff 2026-11-12)

**Aster premise:** Aster has no `unsafe` construct or escape hatch. The current language is scalar-only and cannot express pointers, references, arrays, allocation, deallocation, or FFI; see [`docs/spec/aster-safety.md`](../docs/spec/aster-safety.md). “Safe Rust” and “unsafe” in rows refer only to the cited source/target systems, not an Aster feature.

**Reading-status key:** `Primary full text` means the linked paper was fetched/read for relevant methods and claims in this review. `Selected passages/abstract` is explicitly not a full review. `Metadata/source verified; technical review pending` must not be treated as a complete characterization. “Not established” means no claim found in the reviewed source, not a proof that no other literature exists.

## Provisional categories

- **Already substantially addressed:** Rust-like static ownership/lifetime typing; ownership inference for restricted C→Rust; safe source translation for selected C/C++ subsets; optimizer-driven removal of some dynamic ownership wrappers; borrow inference in a pure functional language; cost-aware C interface type selection.
- **Known combinations:** static analyses plus SMT/borrow-checker oracles; dynamic checks plus compiler optimization; source refactoring plus differential/regression testing; ownership facts feeding reuse/copy elimination.
- **Engineering improvements, not automatic novelty:** one CLI supporting four source languages; using a common IR; using a weighted sum of execution, memory, and edit costs; emitting readable code.
- **Still plausible research questions:** precise source-defined behavior/effect semantics for one bounded cross-language fragment; an independently checked end-to-end translation certificate for a useful ownership/pointer subset; scalability/precision tradeoffs with controlled comparisons. Each is provisional and must be differentiated from formal compilation, translation validation, &inator, Scylla, and Cpp2Rust.
